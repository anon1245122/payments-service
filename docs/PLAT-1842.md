# PLAT-1842 — Add an explicit `Currency` to `PaymentService.charge`

## Problem

`PaymentService.charge(Order)` hard-codes the settlement currency to `USD`:

```java
public Receipt charge(Order order) {
    Currency currency = Currency.USD; // <-- wrong for non-USD accounts
    return gateway.submit(order.id(), order.amountMinor(), currency);
}
```

Accounts now carry a `billingCurrency` (EUR/GBP/JPY). Today a €50 order is submitted
to the gateway as **$50** — a real correctness bug, not just cleanup.

## Proposed signature change

```java
// before
Receipt charge(Order order)

// after
Receipt charge(Order order, Currency currency)
```

## Why this needs a plan (not a one-line edit)

- `charge(Order)` is called from several in-repo modules **and** from the external
  `billing-gateway` service, which links against our published jar.
- A big-bang rename would break external consumers at runtime and risk charging live
  customers in the wrong currency.

## Deliverable

A **`migration_plan.md`** covering:

1. **Caller mapping** — every call site, which module, and the correct currency source.
2. **Rollout order** — the sequence in which callers are migrated.
3. **Compatibility checks** — source / binary / behavioral gates at each step.
4. **Rollback conditions** — what triggers a revert, and the one irreversible step.

> Do the impact analysis and sequencing during review. **Do not** change the
> `charge` signature in this issue.
